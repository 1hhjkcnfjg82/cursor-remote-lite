# Gate「重新配对」设计

日期：2026-11-04  
状态：已确认

## 问题

手机 App 在电脑离线时只显示 `#gate` 遮罩（「电脑不在线…会自动重试…」+「重试」）。自动重试会循环调用 `boot()`，无法进入主界面菜单。菜单里虽有「取消本机配对」，但被 gate 挡住，换电脑时无法重新扫码/粘贴配对。

## 目标

在离线重试界面提供一键「重新配对」：清除本机配对凭证，停止自动重试，回到未配对粘贴/扫码流程。无需二次确认。

非目标：

- 不改配对协议、电脑端 `npm run pair`、Android 壳层 `setup.html`
- 不改自动重试间隔（Pages 15s / 内网 3s）
- 不新增「仅取消重试、保留配对」的中间态

## 交互

当 `gate({ retry: true })`（或传入自定义重试文案字符串）时：

1. 显示现有「重试」按钮（行为不变：调用 `boot()`）
2. 同时显示次要按钮「重新配对」
3. 点击「重新配对」后立即：
   - `clearTimeout(retryTimer)` 停止自动重试
   - 若当前有 `base`，可选 `POST /api/logout`（失败忽略——旧电脑常已离线）
   - `store.set('token', null); store.set('key', null)`
   - `Conn.reset()`
   - `showUnpaired()` 进入粘贴配对链接界面

未显示重试时（配对输入、TOTP、纯提示等），「重新配对」保持隐藏。

## 实现要点

### 文件

| 文件 | 变更 |
|------|------|
| `app/index.html` | `#gate` 增加按钮；`gate()` 显隐；抽取/复用清配对逻辑；绑定 click |
| `app/i18n.js` | 增加「重新配对」→ `Re-pair`（或同等英文） |

### 逻辑复用

抽出共享函数（名称可定 `clearPairing` / `unpairLocal`），供：

1. gate「重新配对」（无确认 → `showUnpaired()`）
2. 菜单 `data-act="logout"`（保留现有 `ask(...)` 确认；确认后同样清凭证 + `Conn.reset()`，并补上 `showUnpaired()`，避免清完后仍停在空白已连 UI）

菜单路径仍保留确认文案；gate 路径按产品决定不确认。

### 样式

沿用 `#gate button` 现有样式；「重新配对」不使用 `.primary`，与「重试」同级次要外观，垂直排列在「重试」下方即可（与现有 flex column gap 一致）。

## 验收

1. 配对后人为让电脑离线（或断网），gate 出现「重试」与「重新配对」。
2. 点「重新配对」后自动重试停止，进入粘贴 `#pair=…` 界面，`localStorage` 无 `cr-token` / `cr-key`。
3. 点「重试」仍可继续 `boot()`，行为与改前一致。
4. 英文界面下按钮文案为对应翻译。
5. 已连接时菜单「取消本机配对」确认后也回到未配对界面。

## 风险

- 旧电脑短暂仍在线时，本机已清凭证但服务端设备记录可能残留；可依赖现有 `/api/logout` 尽力删除，或之后用电脑端 `devices` 清理。可接受。
- 误触会丢配对：产品已选择无确认换电脑速度优先。
